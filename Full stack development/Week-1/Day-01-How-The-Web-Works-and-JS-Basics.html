1. How the Internet Works

Theory — 20 minutes

1.1 What is the Internet?

Simple Answer: The internet is a giant network of computers connected to each other across the world, sharing information.

The internet is a global network of interconnected computers that communicate using standardized protocols (primarily TCP/IP). It's a physical infrastructure of cables (undersea fiber optic cables, copper wires), routers, switches, and servers that enables data transfer between any two connected devices.
🏪 Real-World Analogy — The Postal System
  • Your computer = Your house
  • Server = A warehouse/shop
  • IP Address = Your home address (e.g., 192.168.1.1)
  • Domain Name (google.com) = The shop's name (easier to remember)
  • DNS = The phone directory that converts names to addresses
  • HTTP = The language both sides agree to speak
  • Router = The post office that routes your mail
YOUR COMPUTER  ←→  ROUTER  ←→  ISP  ←→  INTERNET BACKBONE  ←→  SERVER
   (Home)      (Post Office)  (Postal Service)    (Highway)       (Warehouse)

1.2 What Happens When You Type "google.com"?

⚠️ IMPORTANT
This is one of the MOST asked interview questions. You must know every step. Practice explaining this out loud.

Step 1: DNS Resolution (Finding the Address)

You type: google.com
Browser thinks: "I need the IP address of google.com"

DNS (Domain Name System) converts human-readable domain names to IP addresses.

DNS Lookup Process (in order):

  1. Browser Cache — "Have I visited this site recently?"
  2. OS Cache — "Does my operating system know?" (checks /etc/hosts)
  3. Router Cache — "Does my router know?"
  4. ISP's DNS Server — "Ask my internet provider"
  5. Root DNS Server — "I know who manages .com domains"
  6. TLD Server — "I manage all .com domains. google.com → Google's nameserver"
  7. Authoritative DNS Server — "google.com lives at IP 142.250.190.78"

Step 2: TCP Connection (The Three-Way Handshake)

Before sending data, the browser establishes a reliable connection:

Client (Browser)                    Server (Google)
      │                                  │
      │──── SYN (Hey, can we talk?) ────→│
      │                                  │
      │←── SYN-ACK (Sure, let's!) ──────│
      │                                  │
      │──── ACK (Great, we're on!) ─────→│
      │                                  │
      │       CONNECTION ESTABLISHED      │
  • SYN = Synchronize — Client says "I want to connect"
  • SYN-ACK = Synchronize-Acknowledge — Server says "OK, I'm ready too"
  • ACK = Acknowledge — Client says "Let's go!"
📞 Analogy — A Phone Call

1. You dial (SYN) → 2. They pick up and say "Hello?" (SYN-ACK) → 3. You say "Hi! I need something" (ACK)

2.2 Browser Rendering Pipeline (Critical Rendering Path)

⚠️ IMPORTANT
Understanding this pipeline helps you write performant web apps. Interviewers ask "why is my page slow?" — this is the answer. 
HTML ──→ DOM Tree
              │
              ├──→ Render Tree ──→ Layout ──→ Paint ──→ Composite ──→ PIXELS ON SCREEN
              │
CSS  ──→ CSSOM Tree

Step-by-Step Breakdown:

1. Parse HTML → Build DOM (Document Object Model)

<html>
  <body>
    <h1>Hello</h1>
    <p>World</p>
  </body>
</html>

Becomes a tree:

           Document
              │
            <html>
              │
            <body>
           /      \
        <h1>      <p>
         │          │
       "Hello"   "World"

2. Parse CSS → Build CSSOM

CSS rules become a tree of computed styles mapped to DOM elements.

3. Combine DOM + CSSOM → Render Tree

  • Only includes visible elements
  • display: none — excluded from render tree
  • visibility: hidden — included (takes up space)

4. Layout (Reflow)

Calculates exact position and size of each element on screen.

5. Paint

Fills in pixels — colors, text, borders, shadows, images.

6. Composite

Layers are combined in correct order (z-index). GPU acceleration for transforms and opacity.

Where Does JavaScript Fit?

HTML Parsing ──→ Encounters <script> ──→ STOP PARSING ──→ Download JS ──→ Execute JS ──→ Resume

This is why:

  • <script> tags block HTML parsing (render-blocking!)
  • Put <script> at the bottom of <body>, OR use defer/async
Without defer/async:
HTML: ████████░░░░░░████████████
JS:          ████████
             ↑ blocks HTML

With defer:
HTML: ██████████████████████████
JS:          ████████░░░░░░████
                              ↑ executes after HTML done

With async:
HTML: ████████░░░████████████████
JS:          ████████
             ↑ executes when ready (may interrupt)

5. Variables — var, let, const

This is where real JavaScript begins — 25 minutes

5.1 What is a Variable?

A variable is a named container that stores a value in memory.

📦 Analogy — Labeled Boxes
  • The label = variable name
  • What's inside = the value
  • The box type = var, let, or const

5.2 Three Ways to Declare

var name = "Rahul";        // OLD way (ES5) — avoid this
let age = 25;              // NEW way (ES6) — values that change
const country = "India";   // NEW way (ES6) — values that DON'T change

5.3 var — The Problematic One

Problem 1: Function-scoped (NOT block-scoped)

if (true) {
    var x = 10;
}
console.log(x);  // 10 ✅ — var LEAKS out of if/for blocks!

// Compare with let:
if (true) {
    let y = 20;
}
console.log(y);  // ❌ ReferenceError: y is not defined

What is Scope?

  • Scope = Where a variable can be accessed
  • var is function-scoped — available throughout the entire function
  • let/const are block-scoped — only available inside { }
function example() {
    if (true) {
        var a = 1;    // Available in ENTIRE function
        let b = 2;    // Available only in this if-block
        const c = 3;  // Available only in this if-block
    }
    console.log(a);  // 1 ✅
    console.log(b);  // ❌ ReferenceError
    console.log(c);  // ❌ ReferenceError
}

Problem 2: Hoisting

⚠️ MUST KNOW FOR INTERVIEWS
Hoisting is JavaScript's behavior of moving variable and function declarations to the top of their scope BEFORE code execution. Only the declaration is hoisted, NOT the initialization. 
console.log(greeting);  // undefined (NOT an error!)
var greeting = "Hello";
console.log(greeting);  // "Hello"

What JavaScript actually does behind the scenes:

// CREATION PHASE (before your code runs):
var greeting;           // Declaration hoisted, initialized with undefined

// EXECUTION PHASE (your code runs):
console.log(greeting);  // undefined
greeting = "Hello";     // NOW it gets assigned
console.log(greeting);  // "Hello"
"JavaScript execution happens in two phases. In the creation phase, the engine scans the code and allocates memory for all variable and function declarations. var variables are initialized with undefined during this phase. In the execution phase, the code runs line by line and assignments happen."

Problem 3: The Classic Loop Problem

for (var i = 0; i < 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
// Output: 3, 3, 3 (NOT 0, 1, 2!)
// Why? var is function-scoped → only ONE 'i' exists
// By the time setTimeout runs, the loop is done and i = 3

5.4 let — The Modern Variable

let age = 25;
age = 26;           // ✅ Re-assignment allowed
let age = 30;       // ❌ SyntaxError: already declared

Temporal Dead Zone (TDZ)

🚨 TRICKY INTERVIEW POINT
let and const ARE hoisted, but they're placed in a Temporal Dead Zone (TDZ) — you cannot access them before their declaration. 
console.log(a);  // undefined (var → hoisted + initialized)
var a = 10;

console.log(b);  // ❌ ReferenceError: Cannot access 'b' before initialization
let b = 20;      // b IS hoisted, but in TDZ until this line
// ──── TDZ for 'name' starts here ────
// Cannot access 'name' in this zone
// Even though it's hoisted, it's uninitialized
console.log(name);  // ❌ ReferenceError
// ──── TDZ for 'name' ends here ────
let name = "Rahul"; // Declaration + initialization
console.log(name);  // ✅ "Rahul"
"Yes, let is hoisted, but unlike var, it's not initialized with undefined. It stays in the Temporal Dead Zone from the start of the block until the declaration is encountered. Accessing it in the TDZ throws a ReferenceError. This makes let safer than var because it prevents accidental use before definition."

let Fixes the Loop Problem

for (let i = 0; i < 3; i++) {
    setTimeout(function() {
        console.log(i);
    }, 1000);
}
// Output: 0, 1, 2 ✅
// let creates a NEW 'i' for each iteration (block-scoped)

5.5 const — The Constant

const PI = 3.14159;
PI = 3.14;          // ❌ TypeError: Assignment to constant variable

const name;         // ❌ SyntaxError: Missing initializer
                    // const MUST be initialized when declared
🚨 WARNING — const with Objects & Arrays
const does NOT make the value immutable. It only prevents re-assignment of the variable. The contents of objects and arrays CAN still be changed! 
const user = { name: "Rahul", age: 25 };

// ✅ Modifying properties is ALLOWED:
user.name = "Amit";
user.city = "Mumbai";
console.log(user);  // { name: "Amit", age: 25, city: "Mumbai" }

// ❌ Re-assigning is NOT allowed:
user = { name: "New" };  // TypeError!

// Same with arrays:
const colors = ["red", "blue"];
colors.push("green");    // ✅ Allowed
colors = ["new"];        // ❌ TypeError!
"const protects the reference (the pointer to the memory location), not the value itself. Objects and arrays are stored in heap memory, and const only freezes the stack pointer. To make an object truly immutable, use Object.freeze() — but note that it's only shallow."

6.3 Value vs Reference (MUST UNDERSTAND!)

// PRIMITIVES — Copied by VALUE
let a = 10;
let b = a;     // b gets a COPY
b = 20;
console.log(a);  // 10 (unchanged!)

// OBJECTS — Copied by REFERENCE
let obj1 = { name: "Rahul" };
let obj2 = obj1;  // obj2 gets same REFERENCE (pointer)
obj2.name = "Amit";
console.log(obj1.name);  // "Amit" (changed! Same object)

┌──────┐    ┌──────┐          ┌──────┐    ┌──────────────────┐

  Independent copies          ┌──────┐         ↑
                              │ obj2 │─────────┘
                              └──────┘  Both point to SAME object

How to Create a True Copy

// Shallow copy:
const copy1 = { ...original };              // Spread operator

// Deep copy:

8.2 Implicit Coercion (JS does it automatically)

Rule 1: String + anything = String

console.log("5" + 3);       // "53" (3 → "3")
console.log("5" + true);    // "5true"
console.log("5" + null);    // "5null"
console.log("5" + {});      // "5[object Object]"

Rule 2: Other math operators → Number

console.log("5" - 3);       // 2
console.log("5" * 2);       // 10
console.log(true + true);   // 2
console.log("abc" - 1);     // NaN

Rule 3: == vs ===

// === Strict: NO coercion
5 === "5"           // false (different types)

// == Loose: DOES coercion
5 == "5"            // true ("5" → 5)
0 == false          // true (false → 0)
"" == false          // true ("" → 0, false → 0)
null == undefined   // true (special rule)
null == 0            // false
NaN == NaN          // false (NaN ≠ anything)

The Abstract Equality Algorithm (== rules):

  1. Same type? → Compare normally
  2. null == undefined? → true
  3. Number vs String? → Convert String to Number
  4. Boolean vs anything? → Convert Boolean to Number first, then compare
  5. Object vs Primitive? → Convert Object using .valueOf() then .toString()

Example Walkthrough:

"" == false
// Step 1: Boolean vs String → Convert false to Number → 0
// Now: "" == 0
// Step 2: String vs Number → Convert "" to Number → 0
// Now: 0 == 0
// Result: true ✅

🎯 Day 1 — Interview Cheat Sheet

Q: What happens when you type a URL in the browser?
DNS lookup → TCP handshake → TLS handshake (HTTPS) → HTTP request → Server processes → HTTP response → Browser renders (DOM → CSSOM → Render Tree → Layout → Paint → Composite)
Q: Difference between var, let, const?
var is function-scoped and hoisted with undefined. let and const are block-scoped and hoisted but in TDZ. const can't be reassigned but object properties can be mutated.
Q: What is hoisting?
JavaScript moves declarations to the top of their scope during the creation phase. var is initialized with undefined, let/const enter TDZ, function declarations are fully hoisted.
Q: What is TDZ (Temporal Dead Zone)?
The period between entering a block and the let/const declaration being reached. Accessing the variable in TDZ throws ReferenceError.
Q: What are the 8 data types in JavaScript?
Primitives: string, number, boolean, undefined, null, symbol, bigint. Non-primitive: object (includes arrays, functions).
Q: Why is typeof null === "object"?
Historical bug from 1995. Values had type tags — objects used tag 0, null was NULL pointer (0x00) so got tag 0 too. Never fixed because it'd break existing code.
Q: Difference between == and ===?
=== checks type AND value without coercion. == performs type coercion before comparison. Always use ===.
Q: What are falsy values in JavaScript?
false, 0, -0, 0n, "", null, undefined, NaN. Everything else is truthy — including [], {}, and "0".
Q: Difference between null and undefined?
undefined = declared but not assigned (set by JS engine). null = intentionally assigned empty value (set by programmer).
Q: How are primitives different from objects?
Primitives are immutable, stored in stack, compared by value. Objects are mutable, stored in heap, compared by reference.
